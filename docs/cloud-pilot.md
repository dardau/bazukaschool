# BazukaSchool: запуск кабинетов

Статус: код подготовлен; облачный запуск требует проекта Supabase, применения миграции, настройки почты и env Vercel. Не приглашать учеников до прохождения проверки ниже.

## Подключение

1. Отдельный Supabase project. Применить `supabase/migrations/202610210001_school.sql` один раз через SQL Editor / CLI от postgres. Миграция атомарна. Не применять к базе другого приложения.
2. В Authentication → URL configuration установить Site URL `https://bazukaschool.vercel.app` и разрешённые redirect URLs `https://bazukaschool.vercel.app/**`, для локальной проверки `http://127.0.0.1:5187/**`.
3. Оставить email confirmation включённым. Настроить собственный SMTP с подтверждённым отправителем. Встроенная почта Supabase ограничена адресами команды проекта и не подходит для учеников. Не добавлять учеников в команду Supabase ради обхода ограничения. Источник: https://supabase.com/docs/guides/auth/auth-smtp . Установить минимальную длину пароля 10 на стороне Supabase; UI также проверяет 10 символов.
4. В Vercel и локальный `.env.local` добавить `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` из проекта. Только publishable (либо legacy anon) key. Service role / secret key никогда не попадает в клиент, Git, `NEXT_PUBLIC_*` или публичные артефакты. После изменения env нужен rebuild/redeploy.
5. Владелец регистрируется и подтверждает почту. Назначение преподавателя делает администратор в SQL Editor, подставив согласованный email:

```sql
update public.profiles set role='teacher'
where id=(select id from auth.users where email='OWNER_EMAIL' and email_confirmed_at is not null);
```

Проверить ровно одну изменённую строку. В приложении нет регистрации «я учитель», метаданные пользователя не дают роль.

6. Преподаватель открывает «Мой кабинет», создаёт отдельное одноразовое приглашение на ученика. Ученик регистрируется, подтверждает почту, вставляет код. Код действует 7 дней. Приглашения не отправляются через почту/Telegram автоматически.
7. Письменная работа: «Сохранить» сохраняет личный черновик; «Отправить на проверку» создаёт неизменяемую попытку. Новая редакция отправляется новой попыткой. Аудио: запись/файл → прослушать → отправить. Преподаватель видит отправленные работы и агрегированный прогресс; личные заметки и черновики ему не доступны.

## Проверки перед пилотом

- `npm run test:security`: настоящий PostgreSQL движок PGlite, mock только схем auth/storage Supabase. Проверяет SQL RLS, запрет повышения роли, одноразовое приглашение, разные классы, права аудио/фидбека, конфликт версий. Не заменяет реальный Storage/Auth E2E.
- `npx tsc --noEmit`; `npm run build`; ESLint новых cloud компонентов и `lib/cloud`.
- Два отдельных ученика A/B и учитель: регистрация/подтверждение, вход, выход, восстановление пароля; A не видит B. Второй независимый учитель не видит первый класс.
- Два устройства одного ученика: сохранить слово/ответ → загрузить на втором; конфликт одновременного редактирования должен показать ошибку, не затереть первый текст.
- Ученик отправляет текст и короткий аудиофайл → учитель открывает и прослушивает → фидбек → ученик видит его после обновления (автоматический опрос каждые 20 секунд).
- Прямой запрос к private storage без сессии и с токеном другого ученика отклоняется. Приватные signed URLs выдаются на 10 минут.
- Потеря сети при сохранении/отправке не показывает успех. Повторная отправка той же попытки не создаёт дубликат. Аудиочерновики разделены по user ID и question ID в IndexedDB.
- Проверить мобильный Chrome/Android и Safari/iOS с реальным микрофоном: типы MediaRecorder зависят от устройства. Файл можно загрузить как запасной вариант.

## Смена преподавателя

Администратор сначала назначает нового подтверждённого пользователя teacher (SQL выше), затем переносит класс в одной транзакции. Старые отправленные работы и фидбек сохраняются. Значения UUID ниже — заполнители, не реальные данные:

```sql
begin;
update public.enrollments set teacher_id='NEW_TEACHER_UUID' where teacher_id='OLD_TEACHER_UUID';
update public.submissions set teacher_id='NEW_TEACHER_UUID' where teacher_id='OLD_TEACHER_UUID';
-- Старые приглашения истекают, чтобы новые ученики не попадали к прежнему учителю.
update public.invitations set expires_at=now() where teacher_id='OLD_TEACHER_UUID' and used_by is null;
update public.profiles set role='student' where id='OLD_TEACHER_UUID';
commit;
```

Проверить, что новый teacher существует и email подтверждён до транзакции. Исторический `reviews.teacher_id` остаётся автором последнего комментария; при редактировании новым преподавателем меняется на него.

## Хранение и эксплуатация

- В режиме без env прежняя локальная версия остаётся доступной и честно сообщает отсутствие облака.
- При включённом облаке гостевого обхода нет. Предыдущие данные браузера не импортируются автоматически. В кабинете есть отдельный подтверждаемый перенос без перезаписи существующих ключей; преподавателю доступен прежний локальный аудиоархив.
- Пароли обрабатывает Supabase Auth. В приложении нет хранения паролей. Доступ определяется RLS, не кнопками в UI.
- Локальное аудио до отправки не синхронизируется. После отправки в кабинете хранится неизменяемый снимок. На вкладке записи показывается понятный статус; загрузка ограничена 25 МБ.
- Текст синхронизируется после нажатия «Сохранить»; флаги/слова — сразу. Фоновое чтение каждые 30 секунд и при возврате фокуса. Нет обещания offline sync: при потере сети сохранять повторно после восстановления.
- Преподаватель получает работы в кабинете, без внешних email/Telegram уведомлений.
- Пилот не включает оплату, автоматическую оценку IELTS, планировщик уроков или удаление аккаунтов самим учеником. По запросу владелец удаляет аккаунт через Supabase и отдельно его файлы Storage. Не удалять SQL-строки storage.objects напрямую — файлы удаляются через Storage API.
- Перед расширением школы настроить регулярные резервные копии PostgreSQL и Storage; бесплатный тариф не считать резервной копией. Следить за квотами базы, аудио и исходящего трафика в Supabase.
- Если загрузка файла прошла, а создание submission завершилось сетевой ошибкой, объект оставляется для безопасного повтора. Администратор может периодически удалять подтверждённо неиспользуемые старые объекты через Storage API.
